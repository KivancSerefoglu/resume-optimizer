# Resume Optimizer v1.1 — Dossier Mode, Match Score, Direct PDF

**Date:** 2026-07-21
**Status:** Approved by user (chat), pending spec review
**Baseline:** v1.0.0 as merged from branch `build-plugin` (PR #1)

## Summary

Three additions to the existing `resume-optimizer` skill, all inside the one skill (no new
skills, no new plugins):

1. **Background dossier mode** — the skill accepts a reusable master background file and
   generates a one-page, job-tailored CV from the relevant subset of it.
2. **Match score** — the Job Match Analysis section leads with a transparent, auditable
   match percentage.
3. **Direct PDF output** — every successful run writes both `optimized-resume.md` and
   `optimized-resume.pdf` by default; a page-count loop enforces one page in dossier mode.

The non-fabrication core is unchanged. The user's "may slightly change the given
information" is implemented as selection, ordering, phrasing, and job-description
terminology — never altered facts. This decision was made explicitly with the user
(options considered: reword/emphasize only; conservative flagged inference; free
optimization — the first was chosen).

## Goals

- Generate a fresh one-page CV per job application from one maintained `background.md`.
- Make the match assessment quantitative and auditable.
- Remove the "offer PDF" step: PDF is a default artifact.
- Preserve: non-fabrication rules, input security, the 5-step process, the 5-section
  output, resume mode (tailor an existing resume) as it works today.

## Non-goals

- No second skill, command, or agent. One skill runs everything.
- No inference beyond supplied facts (option "reasonable inference" was rejected).
- No DOCX output; no change to the HTML template's structure or class contract.
- No storage of user data inside the plugin directory — `background.md` lives wherever
  the user keeps it.

## Design

### 1. Background dossier mode

**New reference file** `references/background-dossier.md` defining the master-file format:

- A markdown file (suggested name `background.md`, kept anywhere the user likes) with
  sections: Contact, Education, Experience, Projects, Skills, Awards & Publications,
  Extras (volunteering, languages, authorizations the user wants considered).
- Each entry carries everything known: dates, titles, technologies, metrics, links,
  scope, outcomes. Explicitly no length limit — more detail in, better CVs out.
- The file is the single source of truth for facts; the skill quotes facts from it and
  never extends them.

**SKILL.md input handling becomes two modes:**

- **Dossier mode** (new, preferred when a dossier exists): inputs are the dossier file +
  job description. The skill selects the relevant subset and generates a one-page CV.
  Selection is the optimization lever: items may be freely included, excluded, reordered,
  and rephrased; facts within included items stay verbatim-true.
- **Resume mode** (existing behavior, unchanged): inputs are an existing resume + job
  description; the skill tailors the resume.
- Mode is chosen by what the user provides; if they provide both, dossier mode wins and
  the resume is treated as additional evidence for the dossier.

**Bootstrap flow:** when the user has no dossier, the skill offers to build
`background.md` from their existing resume plus targeted questions (metrics, omitted
projects, older experience), writes the file where the user chooses, then proceeds in
dossier mode. Declining the offer falls back to resume mode.

### 2. Match score

The Job Match Analysis output section now leads with:

> **Job match: NN% (estimate of evidence coverage — not an ATS score)**

followed by a breakdown table with one row per major requirement:

| Requirement | Weight | Status | Credit |

- Weights: required qualifications and core responsibilities weigh 2; preferred/nice-to-
  have weigh 1.
- Credit: strongly supported = full weight; partially supported = half; not demonstrated
  or unknown = zero (unknown additionally generates an Information Request).
- NN% = earned credit / total weight, rounded to the nearest 5 to avoid false precision.
- Guardrails (rule text in SKILL.md): the number must never be presented as an official
  or ATS score; the breakdown table must always accompany it; the percentage is computed
  from the classification in Step 3, never adjusted to look better.

### 3. Direct PDF output

Export section of SKILL.md changes from "offer PDF" to:

1. Every successful run writes `optimized-resume.md` AND renders `optimized-resume.pdf`
   (existing flow: copy `assets/resume-template.html`, fill `<main>`, headless Chrome).
2. **Page-count check:** after rendering, determine the PDF's page count —
   `mdls -name kMDItemNumberOfPages optimized-resume.pdf` on macOS, `pdfinfo` if
   available, otherwise open the PDF and check visually.
3. **One-page enforcement (dossier mode only):** if the count exceeds 1, trim the
   lowest-relevance items (per the Step-3 classification), re-render, and repeat until it
   fits. Report what was trimmed in Changes Made. Resume mode keeps the existing rule:
   one page preferred for early-career, a second page acceptable when justified — no
   forced trimming of user-supplied content.
4. Chrome missing: fall back to writing `optimized-resume.html` plus print-to-PDF
   instructions (unchanged from v1).

### 4. Unchanged

Non-fabrication rules, input security, required-inputs questioning discipline, the
5-step process, the 5-section output structure, the HTML template and its class
contract, and resume mode behavior.

## Error handling

- Dossier file unreadable/empty → say so, offer bootstrap flow.
- Page-count tools unavailable → visual check; if impossible, state the uncertainty
  rather than claiming one page.
- All v1 error handling retained (scanned PDFs, blocked URLs, injection text).

## Testing

Extended `examples/sample-run.md` red flags:

- A fact (date, metric, technology, title) appearing in the CV that is not in the
  dossier = regression.
- Match percentage without the breakdown table = regression.
- Match percentage described as an ATS score = regression.
- Dossier items merely *omitted* from the CV = fine (selection is the point).
- Run ends without writing both .md and .pdf (Chrome available) = regression.

Manual smoke test: run the skill in a scratch directory with the fixture dossier + JD;
verify one-page PDF output and the five sections.

## Decisions

- One skill, two modes (user-confirmed: "it should be run by just one skill").
- Fact policy: reword & emphasize only (user-selected).
- Dossier: reusable master file (user-selected).
- Match % rounded to nearest 5; weights 2/1; labeled estimate, never ATS.
