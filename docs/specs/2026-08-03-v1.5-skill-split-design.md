# Resume Optimizer v1.5 — Split Match Analysis Into Its Own Skill

**Date:** 2026-08-03
**Status:** Approved by user (chat), pending spec review
**Baseline:** v1.4.0 as merged to `main` (merge commit c6b9e47)

## Summary

Today one skill does two jobs. `resume-optimizer` evaluates the candidate against a
job description (Steps 1–3) and then writes and exports a tailored résumé (Steps 4–5
plus Export). The evaluation half is useful on its own — deciding whether a role is
worth an evening of effort does not require generating a PDF — but there is no way to
reach it without paying for the whole run.

v1.5 splits the skill in two:

- **`match-analysis`** (new, invoked as `/match-analysis`) — scores one job description
  against the candidate's background and returns an apply/skip verdict. Writes no files.
- **`resume-optimizer`** (unchanged entry point, `/resume-optimizer`) — still produces the
  full five-section output including the match analysis, then exports markdown and PDF.

The shared machinery — evidence extraction, job-description analysis, link harvest,
requirement classification, and the scoring rubric — moves into a plugin-level
`shared/` directory that both skills read. There is exactly one copy of the rubric.

## Design decisions

These were settled in the design conversation and drive everything below.

| Decision | Choice | Rationale |
|---|---|---|
| Motivation | Fast job screening + single-responsibility skills | Both were stated goals; neither requires publishing separately |
| Full résumé flow | Still includes the match analysis | The split adds a cheap entry point; it does not change the full run |
| Batch input | One job description per run | Keeps depth and output format unchanged; screening is repeatable |
| Verdict | Evidence + explicit apply recommendation | Screening implies a decision, so the skill should state one |
| Code sharing | Shared reference layer, no skill-to-skill invocation | One source of truth for the rubric without unreliable skill nesting |
| Link harvest | Opt-in, unchanged | Already runs only when the user supplies a link |
| Step numbering | Stays 1–5 across the two skills | Three existing files cite "the Step-3 classification" by name |

Two approaches were considered and rejected. **Skill-to-skill invocation** (the résumé
skill invokes `match-analysis` for Steps 1–3) is the purest single source of truth, but
skill nesting is the least reliable mechanism available, and the match skill would emit
its apply/skip verdict mid-résumé-run where it is noise — suppressing it conditionally
would push résumé-flow knowledge back into the match skill and defeat the separation.
**Full duplication** (two self-contained skills) is simplest to build and has no path
indirection, but the weights, credit rules, and rounding would exist in two files that
drift silently; the score is the output that most needs to be trustworthy.

### Splitting non-fabrication.md

`non-fabrication.md` contains two kinds of rule, and only one of them is about writing
a résumé.

**Moves to `shared/evidence-rules.md`** — needed by both skills:

- The never-invent list (employers, titles, dates, degrees, technologies, metrics, …)
- Selection vs. alteration
- Team vs. individual contribution
- Harvested evidence: trust model, ownership framing, Projects-and-Skills-only scope
- The input-security paragraph currently inlined in `SKILL.md`

A match score must not credit a requirement on an invented fact, and must not classify
a repository the candidate only contributed to as their own work. Those are evidence
rules, not writing rules.

**Stays in `skills/resume-optimizer/references/non-fabrication.md`** — résumé only:

- The missing-metric protocol
- The Step-5 validation checklist
- The Factual Validation output format, including the Harvested facts subsection

### Layering rule

**Nothing in `shared/` may link into a skill's `references/`.** Links may point within
`shared/`, within a skill, or from a skill up into `shared/` — never downward from
shared into a skill.

Three existing cross-links are affected:

| Current link | Resolution |
|---|---|
| `background-dossier.md` → `non-fabrication.md` | Repoints to `shared/evidence-rules.md`; the rule it cites (selection vs. alteration) moves there |
| `background-dossier.md` → `link-harvest.md` | Both files now in `shared/`; no change beyond the move |
| `non-fabrication.md` → `writing-guide.md` (work-experience exception) | Cross-link dropped from the shared copy. The experience-selection rule is a one-page-CV layout concern, not an evidence concern; it stays in the résumé skill, which already states it in `SKILL.md` under Input modes and output section 2. `shared/evidence-rules.md` states only that omission is allowed and alteration never is. |

`link-harvest.md` has no outgoing links and moves untouched.

### Step numbering

`shared/match-analysis.md` owns Steps 1–3. The résumé `SKILL.md` owns Steps 4–5. The
numbers do not change.

`tailoring.md`, `link-harvest.md`, and the résumé `SKILL.md` all refer to "the Step-3
classification" by name. Keeping the numbering stable means none of those references
need rewriting and none can silently rot.

## `shared/match-analysis.md`

Contains, verbatim from the current `SKILL.md` except where noted:

1. **Step 1 — Extract candidate evidence.** Build the factual record from the dossier
   or résumé; label each item explicitly supported / reasonable wording improvement /
   missing / unsupported.
2. **Step 2 — Analyze the job description.** Target title, career level, required and
   preferred qualifications, core responsibilities, technical skills, domain knowledge,
   leadership expectations, keywords, company type.
3. **Step 2b — Harvest portfolio links.** Only when the user supplied one. Delegates to
   `link-harvest.md`.
4. **Step 3 — Compare candidate with role.** Classify each major requirement: strongly
   supported / partially supported / not demonstrated / unknown because information is
   missing.
5. **The scoring rubric.** Weights (required and core responsibilities = 2;
   preferred = 1), credit (strongly supported = full, partially = half, not
   demonstrated or unknown = 0), `NN% = earned credit ÷ total weight` rounded to the
   nearest 5, mandatory Total row.
6. **The analysis output format.** The score line, the requirement table, and the
   strong / partial / not-demonstrated / missing-information / positioning sections,
   including the `(repo)` status marker for harvested evidence.

It does **not** contain the verdict block. That is specified only in the
`match-analysis` SKILL.md, so the résumé skill omits it without needing a rule to.

## `skills/match-analysis/SKILL.md`

**Name:** `match-analysis` — invoked as `/match-analysis`.

**Description** triggers on scoring or fit questions ("should I apply", "how well do I
fit this role", "score this job against my background") and carries an explicit
redirect: use `resume-optimizer` when the user wants a résumé written.

### Inputs

1. **Background dossier or résumé** (required) — file path or pasted text, same formats
   as today.
2. **Job description** (required) — file, pasted text, or URL.
3. **Portfolio links** (optional) — same opt-in as today; harvest runs only when a link
   is supplied.
4. **Application context** (optional) — career level and anything else that changes how
   a requirement should be read.

### Process

Read `../../shared/match-analysis.md` and `../../shared/evidence-rules.md`, then run
Steps 1–3 including Step 2b when links were supplied.

### Output

The analysis format defined in `shared/match-analysis.md`, followed by the verdict block:

> **Verdict: Apply / Apply with caveats / Skip** — one line of reasoning
> **Highest-leverage gap:** the single requirement that would move the score most

Verdict rules, driven by the Step-3 classification rather than the number alone — a 75%
with a failed hard gate is a Skip, and a 60% with only preferred-qualification gaps is
not. **Evaluate in this order and stop at the first match**, so that a role scoring 60
with three unmet required qualifications resolves to Skip rather than to the caveats band:

1. **Skip** — two or more required qualifications are "not demonstrated", or a hard gate
   fails: work authorization, a mandatory licence or credential, or a stated minimum
   years of experience the candidate meets less than half of.
2. **Apply** — no required qualification is "not demonstrated", and score ≥ 70.
3. **Apply with caveats** — everything else. Must name the caveat and how to address it
   in a cover letter.

Guardrails, because a screening tool that talks the candidate out of good roles is worse
than no tool:

1. **"Unknown because information is missing" never counts toward Skip.** Unknown means
   the skill lacks information about the candidate, not that the candidate lacks the
   qualification. It generates an Information Request instead.
2. **Preferred and nice-to-have gaps never drive a Skip.**
3. **The verdict is advisory and says so.**

### Non-goals

- Writes no files.
- Generates no résumé, and does not read `writing-guide.md`, `tailoring.md`, or the
  résumé template.
- No dossier bootstrap. With no dossier or résumé, it says what it needs and points at
  `resume-optimizer`, which owns the bootstrap flow.
- Offers a handoff to `resume-optimizer` after the verdict.

## `skills/resume-optimizer/SKILL.md` changes

- **Description** gains the reciprocal redirect: use `match-analysis` to score a role
  without writing a résumé. Today's phrase "with a transparent job-match score" is
  reworded so the two skills do not compete for the same trigger vocabulary.
- **Input security** paragraph replaced by a pointer to `shared/evidence-rules.md`.
- **Process** Steps 1–3 (including 2b) replaced by: read `../../shared/match-analysis.md`
  and follow Steps 1–3. Steps 4–5 stay in place and keep their numbers.
- **Output section 1** becomes: produce the Job Match Analysis per
  `shared/match-analysis.md`. Sections 2–5 unchanged.
- Reference links to `background-dossier.md` and `link-harvest.md` repoint to
  `../../shared/`.
- **Export section unchanged**, including the `--no-pdf-header-footer` requirement and
  the page-count ladder.

## Verification

The repository has no test runner. Skills are verified through fixtures in
`examples/sample-run.md`, which pairs an "Expected output shape" with a "Red flags
(= the skill regressed)" list. This change follows that pattern.

**New fixture section: standalone `/match-analysis` run.** Fictional dossier and job
description, expected output shape, and red flags:

- Wrote `optimized-resume.md`, `optimized-resume.html`, or a PDF
- Emitted a résumé, or any of output sections 2–5
- Ran the dossier bootstrap flow
- Score disagrees with its own table arithmetic, or the Total row is missing
- Skip verdict driven by preferred-only gaps
- Skip verdict driven by an "unknown because information is missing" classification
- Verdict presented as authoritative rather than advisory

**Existing fixtures** — the three current sections must still pass unchanged. The full
résumé run still produces all five sections, and must **not** emit a verdict block.

**Link resolution pass.** Confirm every relative link in `shared/` and in both skills
resolves after the move, and that no file in `shared/` links into a skill's
`references/`.
