# v1.10 Humanizer Pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the user's installed `humanizer` skill over every résumé and cover-letter draft, before review and validation, without letting it move a fact.

**Architecture:** One new shared reference, `shared/humanizer-pass.md`, holds the whole procedure: when to skip, how to call the skill, the guardrails, and the revert check. Both writing skills add one step that points at it. Everything here is skill prose: no Python changes. Regressions are pinned as red flags in `examples/sample-run.md`, and links are checked with `scripts/check-links.py`.

**Tech Stack:** Markdown skill files; Claude Code Skill tool (`humanizer:humanizer`, embedded mode).

**Spec:** `docs/specs/2026-11-22-v1.10-humanizer-pass-design.md`

## Global Constraints

- Branch first: work on `feat/humanizer-pass`, never on `main`.
- The skill is invoked as `humanizer:humanizer`, in embedded mode (final text only).
- Protected, verbatim: names, employers, titles, degrees, dates, numbers and approximate figures as worded, technologies, URLs.
- Résumé: subject-less action-verb bullets kept; every `**bold**` marker kept on the same words; en dash kept in date ranges (`Jun 2024 – Present`); no personality or first person.
- Bold budget after the pass: ≤2 per bullet, ≤10 per page.
- Not installed → skip, report `**Humanizer:** skipped: humanizer not installed` in Factual Validation (the spec's "pass skipped" line, in the report format below), suggest installing once; rest of run unchanged.
- `shared/` must not link into `skills/` (enforced by `scripts/check-links.py`). Name skill references in plain text there.
- Version becomes `1.10.0` in `plugins/resume-optimizer/.claude-plugin/plugin.json`.
- Unchanged: `match-analysis`, cover-letter review mode, all export steps, the reviewer agent brief.

## Review Focus

1. **Humanizer not installed** (most installs). Expect the pass skipped with the exact line, and no other step affected. Pinned by red flag in Task 1 and Task 2.
2. **Date-range en dashes stripped** (humanizer §14 cuts all dashes). Expect `Jun 2024 – Present` intact after the pass. Pinned in Task 1.
3. **Approximate figure reworded** ("roughly halving" → "about 50%"). Expect it reverted. Pinned in Task 1.
4. **Non-English letter** (Preferences letter language). Humanizer's patterns are English. Expect the pass skipped with `skipped: <language> draft`. This is my call, beyond the spec. Pinned in Task 2.
5. **Humanizer returns its audit instead of text** (called outside embedded mode). Expect only the final rewrite used, never the draft/audit bullets pasted into the document. Pinned in Task 1.

- [ ] **Step 4: Write `shared/humanizer-pass.md`**

Open with one paragraph: runs the user's installed humanizer over a finished draft so it does not read as AI-written, without moving a fact. Résumé Step 5b and cover-letter Step 5 call it. Then the sections named in Interfaces, with this content:

- **When to skip:** `humanizer:humanizer` absent from the session's skill list → `skipped: humanizer not installed`, suggest installing the humanizer plugin once. Draft not in English → `skipped: <language> draft`. Skipping changes nothing else in the run.
- **How to call:** Skill tool, `humanizer:humanizer`, embedded mode. Pass the draft (résumé as its markdown; letter as plain text), then the guardrail sections for that document type, stated as overriding humanizer's own rules. Keep only the final text returned. Never paste its draft or audit.
- **Guardrails for every document:** the protected list from Global Constraints, worded verbatim ("roughly halving" stays "roughly halving"). No new fact, metric, tool or claim. Section headings and order unchanged.
- **Résumé guardrails:** the résumé line from Global Constraints. Plus: no bullet added, dropped, merged or split (structure is Steps 4–5's job and the page limit's), and dashes removed only outside date ranges.
- **Letter guardrails:** voice allowed in the register Choices Made names; the cover-letter skill's voice reference (`letter-voice.md`, named in plain text, not linked) outranks humanizer where they differ; salutation, closing and signature untouched.
- **After it returns:** compare with the pre-pass draft. Revert any edit that touches a protected item, a date-range dash or a bold marker, or that adds a claim. Résumé: recount bold against the budget. Count kept and reverted edits.
- **What to report:** the Factual Validation line from Interfaces. Changes Made (résumé) or Choices Made (letter): a one-line summary of what changed, plus each reverted edit with its reason.
