# Resume Optimizer v1.2 — MCS Template Layout + Include-All-Experience Rule

**Date:** 2026-07-22
**Status:** Approved by user (chat), pending spec review
**Baseline:** v1.1 as merged to `main` (merge commit 607ac26)

## Summary

Two changes to the one existing skill:

1. **MCS template layout.** Generated resumes (markdown and PDF, both modes) follow the
   user's accessible MCS-style resume template: centered name, one contact line, fixed
   section order (Education → Experience → Leadership & Activities → Skills & Interests),
   two-line entry headers (organization left / location right, then title left / dates
   right), action-verb bullets without personal pronouns.
2. **Include-all-experience rule.** Every work experience appears in the output with at
   least the two-line header and one bullet, as a strong default. An experience may be
   omitted only when it is clearly irrelevant to the target job, and every omission must
   be named in Changes Made. The one-page trim ladder cuts bullets before jobs.

The user's source template file (Harvard-branded DOCX) is NOT added to the repo; the
repo's HTML template reproduces only the layout, with fictional data.

## Layout specification (from the user's template)

- **Header:** name centered; below it one centered contact line separated by `•`:
  `City, State • email • phone (optional) • links`.
- **Section order (fixed):**
  1. Education
  2. Experience
  3. Leadership & Activities — only when the source material has such items
  4. Skills & Interests
- **Education entries:** line 1 = institution (left) + city, state (right); line 2 =
  degree/concentration, optional GPA (left) + graduation date (right); optional lines:
  thesis, relevant coursework, honors.
- **Experience / Leadership entries:** line 1 = organization (left) + city, state or
  "remote" (right); line 2 = position title (left) + `Month Year – Month Year` (right);
  then bullets. Bullets start with an action verb, no personal pronouns, phrase not
  sentence, quantified where supported.
- **Skills & Interests:** labeled bullet lines, e.g. `Technical: …`, `Language: …`,
  `Interests: …` (labels included only when the source has content for them).
- Section-order flexibility in `references/tailoring.md` is subordinated: the template's
  order is fixed for output; tailoring governs emphasis and selection *within* sections.

## Include-all-experience rule

- Default: every Experience entry from the dossier (or supplied resume) appears with at
  minimum its two-line header plus one bullet.
- Exception: an experience that is clearly irrelevant to the target job may be omitted.
  "Clearly irrelevant" is a high bar — when in doubt, include with one bullet. Every
  omitted experience must be listed by name in Changes Made.
- One-page trim ladder (dossier mode), in order:
  1. Cut bullets from the least job-relevant experiences (floor: 1 bullet per included
     experience).
  2. Trim Projects, Leadership & Activities items, optional Education lines (coursework,
     thesis).
  3. Only then consider omitting a clearly irrelevant experience (named in Changes Made).
  4. If everything is minimal and it still overflows, stop and tell the user.
- Resume mode: unchanged (no forced trimming), but the layout rules above still apply to
  the rendered output.

## Error handling

Unchanged from v1.1, plus: if the trim ladder reaches step 4, report the overflow instead
of silently dropping content.

## Testing

- Template renders to a one-page PDF with the fictional data (headless Chrome check).
- Fixture red flags: work experience absent with no Changes Made note; section order not
  Education → Experience → (Leadership) → Skills; entry missing its location or dates.
- `claude plugin validate .` passes.

## Decisions

- Layout applies to BOTH modes' output.
- Include-all is a strong default with a "clearly irrelevant" escape hatch (user-refined).
- User's DOCX stays out of the repo.
- Version 1.2.0.
